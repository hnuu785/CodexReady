# Demo & Submission Checklist

## 제품

- [ ] 새 시크릿 브라우저에서 공개 URL이 열린다.
- [ ] 첫 화면만 보고 대상 사용자와 가치가 이해된다.
- [ ] 핵심 흐름이 90초 안에 끝난다.
- [ ] 로딩, 오류, 빈 상태가 데모를 막지 않는다.
- [ ] 휴대폰 화면에서도 핵심 버튼과 결과가 보인다.
- [ ] `/api/health`가 HTTP 200을 반환한다.

## 영상

- [ ] 문제와 사용자를 15초 안에 설명한다.
- [ ] 실제 제품 입력 → 처리 → 결과를 끊지 않고 보여준다.
- [ ] 미리 녹화한 안전한 백업 영상이 있다.
- [ ] 개인 키, 이메일, 알림, 브라우저 북마크가 노출되지 않는다.
- [ ] 링크 권한을 로그아웃 상태에서 확인했다.

## 제출물

- [ ] GitHub 저장소 접근 권한
- [ ] 배포 URL
- [ ] 데모 영상 URL
- [ ] Codex Build Log
- [ ] Value & Viability
- [ ] 프로젝트 한 문장 소개와 핵심 기능
- [ ] README 로컬 실행 방법

## 제출 직전

- [ ] 커밋되지 않은 핵심 변경이 없다.
- [ ] 저장소에 `.env.local`이나 실제 키가 없다.
- [ ] `npm test`와 `npm run build`가 통과한다.
- [ ] 제출 폼의 모든 링크를 다른 팀원이 다시 열었다.
- [ ] 제출 완료 화면을 캡처했다.

## 행사 종료 후

- [ ] 유지하지 않을 RunPod endpoint의 Active workers를 0으로 확인하거나 삭제한다.
- [ ] 유지하지 않을 AWS 리소스를 `npm run cleanup:aws`로 정리한다.
- [ ] 공유한 API 키를 회전하거나 폐기한다.
